# Secure Android OTP SMS Gateway

An enterprise-ready, high-security Android SMS Gateway native client written in Kotlin + Jetpack Compose. This application transforms any dedicated Android mobile device into a cellular SMS OTP forwarding Node for backend systems.

---

## 🔒 Security & Fraud Defense Architecture

This module implements multiple layers of secure execution controls:
1. **Dynamic HMAC-SHA256 Signatures**: Every incoming FCM request is cryptographically validated using a unique shared pairing secret stored locally under secure hardware storage (`EncryptedSharedPreferences`). This prevents command forging.
2. **Epoch Timestamps / Replay Defense**: Incoming payloads undergo checking for absolute time skews. Messages older than 120 seconds are discarded immediately prior to processing.
3. **Sliding-Window Rate Limiter**: Implemented locally on-device. Caps cellular radio transmissions to a customizable rate limit (e.g., maximum 5 SMS/min and 100 SMS/day) to prevent software loops from causing loops of cellular bills.
4. **Data Masking Protocol**: To comply with privacy standards, verification code values (OTPs) match masking rules. Detailed verification strings are completely filtered from the Room log collection unless explicitly overridden via app Debug Mode.

## 🛰️ Cloud Sync & Integration Contracts

The client communicates with your backend APIs to coordinate pairing handshakes and cellular carrier delivery updates.

### 1. Device Pairing (Registration)
* **Endpoint**: `POST {BACKEND_BASE_URL}/api/device/register`
* **Authorization Headers**: `Authorization: Bearer <Admin_Pairing_Token>`
* **Request Payload**:
```json
{
  "device_name": "Pixel 8 Pro Enterprise",
  "android_version": "Android 14 (API 34)",
  "app_version": "1.0.0",
  "fcm_token": "FCM_REGISTRATION_TOKEN"
}
```
* **Response Payload Expectations**:
```json
{
  "device_token": "SECURE_DEVICE_TOKEN_KEY"
}
```

### 2. FCM Broadcast Schema (`SEND_SMS` Type)
Targeting the cellular device from your backend requires dispatching an FCM data packet with this secure construction:
```json
{
  "type": "SEND_SMS",
  "request_id": "tx_req_99818",
  "mobile": "+919876543210",
  "message": "Your verification code is 482019. Expires in 5 minutes.",
  "client_id": "auth-service-node-4",
  "signature": "COMPUTED_HMAC_SHA256_STRING",
  "timestamp": "1717596000"
}
```

#### HMAC Computation Formula:
The signature parameter is generated by calculating standard HMAC-SHA256 across all major payload strings separated by colons (`:`), using your paired `device_token` as the secret key:
```kotlin
val hmacInput = "SEND_SMS:tx_req_99818:+919876543210:Your verification code is 482019...:auth-service-node-4:1717596000"
val calculatedSignatureBytes = HmacSHA256(hmacInput, secret = devToken)
```

### 3. SMS Transmission & Delivery Reports
The client fires active reports to track status (sent, failed, delivered) for every inbound dispatch request.
* **Endpoint**: `POST {BACKEND_BASE_URL}/api/device/sms/status`
* **Authorization Headers**: `Authorization: Bearer <device_token>`
* **Payload**:
```json
{
  "request_id": "tx_req_99818",
  "status": "delivered",
  "error": null,
  "timestamp": "2026-06-10T12:00:00Z"
}
```

## 🛠️ Stack & Module Composition

- **UI Framework**: Jetpack Compose 1.5+ relying on Material 3.
- **Architectural Pattern**: MVVM with reactive data streams.
- **Persistence Layer**: Jetpack Room for persistent local storage.
- **Background Pipeline**: WorkManager `StatusReportWorker` with exponential backoff for offline operation recovery.
- **Network Stack**: Retrofit with OkHttp logs.
- **Execution Engine**: Android Foreground Service bound to persistent notificational metrics for real-time status updates.
